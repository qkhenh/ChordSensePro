\section{System Overview}

\subsection{System Description}
\textbf{ChordSense Pro} is an AI-powered interactive music practice platform for instrumentalists ---
pianists, guitarists, and songwriters. The system integrates a \textbf{Cascaded Hierarchical LoRA}
fine-tuned \textbf{MERT-v1-330M} model for Automatic Chord Recognition (ACR), a \textbf{Client-Side
Harmonic Engine} for real-time music theory analysis, and a \textbf{synchronized interactive workspace}
built on the Web Audio API.

The platform solves a concrete problem: musicians who practice with recordings have no tool that (1)
detects chords automatically with extended-chord accuracy, (2) explains the harmonic function of each
chord (Roman numerals, scale mapping), and (3) embeds all practice tools --- loop, metronome, speed
shift, chord dictionary --- in a single synchronized interface.

\noindent \textbf{Key capabilities:}
\begin{itemize}
    \item \textbf{AI Chord Recognition:} User imports a song via YouTube URL or audio upload. The AI
    pipeline performs source separation (Demucs), beat tracking (madmom), and chord detection (MERT +
    LoRA Hierarchical) to produce a full chord event timeline.
    \item \textbf{Smart Bar-Based Grid:} A beat-aligned chord grid rendered with sub-100ms
    synchronization. Clicking any bar seeks audio playback to that exact timestamp.
    \item \textbf{Client-Side Harmonic Engine:} Each chord is automatically annotated with its Roman
    numeral function (I, ii, V7\ldots) relative to the detected key, and mapped to a recommended scale
    (Ionian, Dorian, Mixolydian\ldots) --- computed entirely in the browser with zero network latency.
    \item \textbf{A/B Loop and Practice Tools:} Drag-select bars to create seamless A/B loops. A Web
    Audio API metronome and pitch-preserving speed shift ($0.5\times$, $0.75\times$) support targeted
    practice.
    \item \textbf{Chord Dictionary with Synthesizer:} Interactive fingering diagrams (Guitar Fretboard /
    Piano Keyboard) and an in-browser Soundfont Synthesizer render audible voicings on demand.
    \item \textbf{Edit Marker and Cloud Sync:} Users correct AI-detected chords; the Harmonic Engine
    recalculates annotations instantly. All analyses and edits are persisted in PostgreSQL and synced to
    personal playlists.
    \item \textbf{Real-Time Practice Mode:} Live microphone chord inference with visual/auditory feedback
    against the target chord in the loaded piece ($<$200ms end-to-end latency).
\end{itemize}

\noindent \textbf{Architecture layers:}
\begin{itemize}
    \item \textbf{Presentation Layer:} React.js SPA (Vite-based) with a custom design system for the interactive
    workspace (Smart Grid, synchronized audio player, A/B loop, Chord Dictionary with audio synthesizer, and VexFlow sheet visualization).
    \item \textbf{Client-Side Harmonic Engine:} High-performance JavaScript module running entirely in the browser,
    performing context-aware Roman numeral analysis, scale mapping, and chord simplification (Basic/Precise mode) with zero server round-trip latency.
    \item \textbf{Application Layer:} Python FastAPI backend providing asynchronous RESTful endpoints (JWT authentication, song charts, playlist management, dictionary queries, student progress tracking) and WebSocket notifications.
    \item \textbf{Data Pipeline Orchestration Layer:} Apache Airflow 2.8 managing scheduled and event-triggered ETL DAGs (\texttt{dag\_ingest\_raw}, \texttt{dag\_process\_audio}, \texttt{dag\_analytics\_rollup}) with Redis caching.
    \item \textbf{AI Processing Service:} Python service integrating Meta AI's Demucs (harmonic stem isolation), madmom (beat tracking), Librosa (chroma CQT and spectrograms), and HuggingFace MERT-v1-330M with Cascaded 3-Head LoRA for extended chord recognition.
    \item \textbf{Data \& Storage Layer:} Hybrid persistence architecture comprising PostgreSQL 16 (relational entities, JSONB chord timelines, auto-initialized via \texttt{init/init.sql}, connected via \texttt{psycopg2-binary} connection pooling without ORM overhead) and MongoDB 7.0 (staging queue for raw audio jobs, binary audio, mel-spectrogram matrices, and cached stems).
\end{itemize}

\section{Business Requirements}

\subsection{Business Context}
Musicians and learners who rely on digital recordings for practice face four key challenges:
\begin{itemize}
    \item \textbf{No Harmonic Context:} Existing chord detection tools (Chordify, ChordAI) output raw
    chord labels without explaining harmonic function (Roman numerals, scale relationships), making it
    impossible to understand progression logic or transpose confidently.
    \item \textbf{Fragmented Practice Workflow:} Musicians juggle multiple disconnected tools: a media
    player, a chord chart app, a standalone metronome, and a fingering reference.
    \item \textbf{Rigid AI Output:} No existing tool allows overriding incorrect AI chord labels.
    Switching between simplified and extended chord views requires a slow server round-trip.
    \item \textbf{No Extended Chord Support for Vietnamese Music:} Extended chord recognition quality
    (9th, 11th, 13th chords) is particularly poor for Vietnamese pop and ballad music, which has unique
    harmonic characteristics underrepresented in international training datasets.
\end{itemize}

\begin{tcolorbox}[colback=white!95!gray, colframe=black,
    title={Scenario 1: Learning Flow -- Import, Analyze, and Study a Song (HOTL)}]
\begin{itemize}
    \item[\textbf{Step 1:}] \textbf{User imports music.} Pastes a YouTube URL or uploads an audio file.
    The system dispatches an analysis job to the AI Processing Service queue.
    \item[\textbf{Step 2:}] \textbf{AI pipeline runs autonomously (HOTL --- fully automated).}
    \begin{itemize}
        \item \textbf{[Auto]} yt-dlp downloads audio as WAV. Demucs isolates the harmonic instrument stem.
        \item \textbf{[Auto]} madmom detects beat grid and time signature.
        \item \textbf{[Auto]} MERT + LoRA Hierarchical predicts chord events containing root note, quality, extension, and confidence score.
        \item \textbf{[Auto]} Key detection runs on the full chord sequence for Roman numeral disambiguation.
        \item \textbf{[Auto]} Client-Side Harmonic Engine maps each chord to its Roman numeral and recommended scale.
    \end{itemize}
    \item[\textbf{Step 3:}] \textbf{Smart Grid rendered.} The frontend renders the chord grid synchronized
    to the audio player. No user action was required during Steps 1--3.
    \item[\textbf{Step 4:}] \textbf{Optional human intervention (HOTL monitor).} The user reviews the
    output. If a chord is incorrectly detected, the \textbf{Edit Marker} allows override. The Harmonic Engine
    recalculates annotations immediately, client-side.
\end{itemize}
\end{tcolorbox}

\begin{tcolorbox}[colback=white!95!gray, colframe=black,
    title={Scenario 2: A/B Loop Practice -- Targeting a Difficult Passage}]
\begin{enumerate}
    \item The user identifies a difficult chord transition in the Smart Grid.
    \item The user drag-selects the target bars to activate A/B Loop mode.
    \item The system loops that passage continuously with the Web Audio API metronome enabled.
    \item The user adjusts playback speed to 0.5x (pitch preserved). After mastering, progresses to 1.0x.
    \item For each chord in the loop, the user clicks to open the Chord Dictionary and views the fingering diagram and hears the voicing via the Soundfont Synthesizer.
\end{enumerate}
\end{tcolorbox}

\begin{tcolorbox}[colback=white!95!gray, colframe=black,
    title={Scenario 3: Real-Time Practice Mode (HITL)}]
\begin{enumerate}
    \item The user has loaded a song and opens the Real-Time Practice tab.
    \item The system activates the microphone and begins real-time chord inference ($<$200ms latency).
    \item The user plays along to the song. The system compares the AI-recognized live chord against the target chord in the Smart Grid at the current playback position.
    \item Correct chords are highlighted \textbf{green}. Incorrect chords are highlighted \textbf{red} with the expected chord name displayed.
    \item The user (Human-in-the-Loop) responds to the AI feedback by adjusting their playing technique in real time.
    \item Practice session accuracy data is logged to the user's profile for progress tracking.
\end{enumerate}
\end{tcolorbox}

\begin{tcolorbox}[colback=white!95!gray, colframe=black,
    title={Scenario 4: Music Platform Manager -- AI Quality Oversight (HOTL)}]
\begin{enumerate}
    \item The \textbf{Music Platform Manager (Business Admin)} logs into the Admin Dashboard.
    \item Reviews AI Quality KPI panel: accuracy by chord class, confidence score histogram, and user correction rate.
    \item Identifies that extended chord accuracy for \texttt{maj9} and \texttt{min11} has dropped below the 75\% threshold.
    \item Flags these chord classes for model re-evaluation and notifies the \textbf{Platform System Administrator (IT Admin)}.
    \item The Platform System Administrator deploys a new fine-tuned LoRA adapter targeting the underperforming classes.
\end{enumerate}
\end{tcolorbox}

\subsection{Key User Groups}

ChordSense Pro defines four user groups, including two specialized administrative roles established to ensure operational integrity and platform governance:

\begin{itemize}
    \item \textbf{Musician / Learner (Primary End User):} Instrumentalists, music students, and hobbyists who import songs, study harmonic structures, practice with A/B Loop and Chord Dictionary, and improve technical performance in Real-Time Practice Mode.
    \item \textbf{Music Producer / Educator (Advanced End User):} Instructors and arrangers who transcribe complex harmonic progressions and utilize the Smart Grid as an interactive pedagogical visual aid.
    \item \textbf{Music Platform Manager (Business Admin):} Oversees educational content quality, monitors AI chord recognition accuracy metrics, manages learner accounts, curates official practice playlists, and moderates user-submitted chord revisions.
    \item \textbf{Platform System Administrator (IT Admin / CIO):} Manages computational infrastructure, deploys and monitors fine-tuned LoRA model adapters, oversees automated Airflow data pipelines, enforces system security, and ensures high availability.
\end{itemize}

\subsection{Data Requirements}
\begin{itemize}
    \item \textbf{User Data:} Credentials, profile information, and roles for authentication and
    access control.
    \item \textbf{Song Analysis Data:} Full chord event timeline per song containing timestamp, root, quality, extension, confidence, and user override status, along with musical key, tempo, and time signature.
    \item \textbf{User Edit History:} All Edit Marker chord overrides per song per user --- enabling
    diff comparison between AI output and user-curated versions.
    \item \textbf{Playlist Data:} User-defined playlists with ordered song references and custom metadata.
    \item \textbf{AI Model Metadata:} Version-controlled LoRA adapter registry with accuracy metrics per
    chord class per model version, maintained by the Platform System Administrator.
    \item \textbf{Training Dataset:} VN Piano Extended Chord Dataset --- labeled audio segments mapped
    to chord labels (root, quality, extension) for model fine-tuning and evaluation.
    \item \textbf{Practice Session Logs:} Per-session records: target chord sequence, recognized chord
    sequence, timestamps, and per-chord correctness flags for progress analytics.
\end{itemize}

\section{AI Processing Pipeline Implementation}

The AI Processing Service and Data Engineering Pipeline form the computational backbone of
ChordSense Pro. The architecture couples an asynchronous backend service for interactive client
requests with an automated data pipeline orchestrator for batch audio processing. Staging between
pipeline phases is managed through document-based temporary storage, while final analytical outputs
are persisted in the relational database.

\begin{tcolorbox}[colback=white!95!gray, colframe=black, title=AI Processing Pipeline --- Step-by-Step Architecture]
\begin{enumerate}
    \item \textbf{Audio Acquisition and Normalization}:
    \begin{itemize}
        \item Ingestion via YouTube URL or direct user file upload (MP3, WAV, FLAC).
        \item Audio is converted and normalized into standard mono 44.1\,kHz WAV format for consistent spectral fidelity.
    \end{itemize}
    \item \textbf{Harmonic Source Separation (Demucs)}:
    \begin{itemize}
        \item Demucs separates the composite audio mix into four distinct stems: drums, bass, vocals, and harmonic accompaniment (piano/guitar).
        \item Isolating the harmonic stem eliminates percussive transients and vocal formants that frequently obscure subtle extended chord partials.
    \end{itemize}
    \item \textbf{Beat and Downbeat Tracking (madmom)}:
    \begin{itemize}
        \item A recurrent neural network beat tracker identifies musical tempo (BPM), beat locations, and measure downbeats.
        \item Beat timestamps establish musically meaningful segmentation boundaries rather than arbitrary fixed time windows.
    \end{itemize}
    \item \textbf{Audio Segmentation and Spectral Representation}:
    \begin{itemize}
        \item Audio is divided into 2-second overlapping windows centered around detected beat boundaries.
        \item Each segment is transformed into multi-resolution spectral features (Mel-spectrogram and Constant-Q Transform).
    \end{itemize}
    \item \textbf{Hierarchical Neural Chord Inference (MERT + LoRA)}:
    \begin{itemize}
        \item Pre-trained MERT acoustic encoder extracts high-level musical embeddings for each segment.
        \item Fine-tuned Low-Rank Adaptation (LoRA) heads predict chord components in a cascaded hierarchy: Root note $\rightarrow$ Chord Quality $\rightarrow$ Chord Extension.
    \end{itemize}
    \item \textbf{Post-Processing and Harmonic Analysis}:
    \begin{itemize}
        \item Viterbi sequence smoothing eliminates momentary chord flickering across adjacent beats.
        \item Global key detection determines the song's musical scale and maps each chord to its Roman numeral harmonic degree (e.g., I, IV, V).
    \end{itemize}
    \item \textbf{Workspace Synchronization}:
    \begin{itemize}
        \item The verified chord timeline and structural metadata are stored in the database.
        \item Aligned event streams are transmitted to the web application for synchronized playback in the Smart Grid.
    \end{itemize}
\end{enumerate}
\end{tcolorbox}

\subsection{Analysis of Problems \& Solutions}

\noindent \textbf{1/ Extended Chord Ambiguity (Core Project Challenge)}
\begin{itemize}
    \item \textbf{Problem:} Extended chords share substantial pitch-class content with basic triads (e.g., A minor 7th and C major 6th contain identical notes), causing flat classification models to misclassify complex chords as simpler variants.
    \item \textbf{Solution:} Cascaded Hierarchical Conditioning --- The prediction is decomposed into three sequential stages where the extension classifier receives the predicted root note and chord quality as structural context, effectively resolving pitch ambiguity.
\end{itemize}

\noindent \textbf{2/ Imbalance in Musical Datasets}
\begin{itemize}
    \item \textbf{Problem:} Common diatonic triads occur hundreds of times more frequently than rare extended chords (such as 9th, 11th, and 13th chords), biasing standard classifiers toward basic chords.
    \item \textbf{Solution:} Focal loss down-weights easily classified common triads, directing model optimization toward difficult extended chords. Pitch-shifting data augmentation across semitones further expands rare chord instances.
\end{itemize}

\noindent \textbf{3/ Multi-Instrument Polyphonic Interference}
\begin{itemize}
    \item \textbf{Problem:} Commercial audio mixes contain loud drums, bass lines, and vocal tracks that obscure subtle harmonic overtones of piano and guitar chords.
    \item \textbf{Solution:} Demucs source separation filters out percussive and vocal stems prior to inference, ensuring that only harmonic accompaniment signals are processed.
\end{itemize}

\noindent \textbf{4/ Chord Flickering Across Time Frames}
\begin{itemize}
    \item \textbf{Problem:} Frame-level audio inference produces noisy predictions with erratic, single-frame chord fluctuations.
    \item \textbf{Solution:} Beat-synchronous segmentation aligns analysis windows to musical beats, followed by Viterbi sequence smoothing to enforce musically consistent transitions.
\end{itemize}

\noindent \textbf{5/ Real-Time Feedback Latency}
\begin{itemize}
    \item \textbf{Problem:} Running large Transformer models during live instrument practice can introduce perceptible delays, degrading the interactive learning experience.
    \item \textbf{Solution:} Exporting the merged model into an optimized inference format reduces execution time to under 100\,ms, while music theory calculations are executed client-side in the browser.
\end{itemize}

\section{AI Model --- Automatic Chord Recognition}

The artificial intelligence component of ChordSense Pro is responsible for Automatic Chord
Recognition (ACR) on piano music: transcribing acoustic audio into a synchronized sequence of
symbolic chord annotations comprising root pitch, chord quality, and harmonic extension. This section
describes the problem overview, literature review and comparative analysis, dataset curation, model
selection, training configuration, evaluation benchmarks, the end-to-end recognition pipeline, and
practical engineering challenges encountered.

\subsection{Problem Overview}

In modern popular music and Vietnamese contemporary ballads (V-Pop), song arrangements frequently
incorporate extended and altered chords (such as 7th, 9th, 11th, and suspended chords) that define the
emotional character of the music. Standard off-the-shelf recognition tools often collapse these rich
harmonies into basic major or minor triads, failing to capture the nuance required for music education
and accompaniment practice.

To establish a solid technical and pedagogical foundation, the project adopts a \textbf{Piano-First}
development scope:
\begin{itemize}
    \item \textbf{Full Harmonic Range:} The piano encompasses 88 keys spanning over seven octaves, providing a comprehensive acoustic testbed for chord recognition across bass, middle, and treble registers.
    \item \textbf{Complex Chord Voicings:} Pianists regularly employ rootless voicings, drop voicings, and extended voice leading that distribute chord tones across octaves, creating challenging acoustic patterns.
    \item \textbf{Pedagogical Standard:} The piano is the universal reference instrument in music theory education. Establishing accurate extended chord recognition on piano creates the core foundation for subsequent expansion to other instruments.
\end{itemize}

\subsection{Literature Review \& Comparative Analysis}

Automatic Chord Recognition has evolved across three major technological phases:
\begin{itemize}
    \item \textbf{Template-Based Methods and Hidden Markov Models (2005--2014):} Early systems computed 12-dimensional chromagrams and matched them against hand-crafted chord templates, using HMMs to model chord transition rules. While computationally light, these methods proved rigid and inaccurate for complex chords.
    \item \textbf{Deep Convolutional and Recurrent Networks (2016--2020):} Convolutional neural networks (CNNs) trained on log-frequency spectrograms significantly improved triad detection accuracy. However, performance on extended chords remained limited due to small training datasets and spectral interference from accompaniment instruments.
    \item \textbf{Pre-Trained Foundation Transformers (2023--Present):} Large-scale self-supervised audio models, such as MERT pre-trained on 160,000 hours of music audio, capture rich acoustic representations of pitch, timbre, and harmony, enabling high-accuracy downstream MIR tasks via parameter-efficient fine-tuning.
\end{itemize}

\subsection{Dataset}

To provide robust training and evaluation coverage across standard and extended chord vocabularies, the team combined established international corpora with a specialized local dataset:

\begin{itemize}
    \item \textbf{McGill Billboard Dataset}: Standard academic benchmark containing 1,000 pop/rock songs with expert chord transcriptions.
    \item \textbf{JAAH (Jazz Audio-Aligned Harmony)}: 300 jazz recordings containing extensive extended, altered, and inverted chord annotations.
    \item \textbf{ChoCo Corpus}: Large-scale integrated music corpus providing diverse chord progression annotations.
    \item \textbf{VN Piano Extended Chord Dataset}: A dedicated collection of 100 Vietnamese pop and ballad piano recordings featuring rich 7th, 9th, and 11th chord progressions, manually transcribed and augmented via pitch-shifting across semitones.
\end{itemize}

The combined dataset is divided into three subsets following standard machine learning practice:
\begin{itemize}
    \item \textbf{Training set}: $\approx$ 70\% of total audio segments
    \item \textbf{Validation set}: $\approx$ 20\% of total audio segments
    \item \textbf{Test set}: $\approx$ 10\% of total audio segments
\end{itemize}

\subsection{Model Selection and Training Environment}

The team selected \textbf{MERT-v1-330M} as the acoustic foundation backbone combined with \textbf{Low-Rank Adaptation (LoRA)} for parameter-efficient fine-tuning:

\begin{itemize}
    \item \textbf{Rich Musical Representations:} MERT was pre-trained on 160,000 hours of music audio using self-supervised learning conditioned on acoustic codebook and spectral teachers, yielding strong representations of timbre, pitch, and harmony.
    \item \textbf{Parameter-Efficient Fine-Tuning (LoRA):} Rather than updating all 330 million parameters, LoRA freezes the pre-trained weights and attaches lightweight trainable adapter matrices to the attention layers. This adapts only approximately 1.2\% of the model parameters, drastically reducing memory usage, preventing catastrophic forgetting, and enabling reproducible training within student compute resources.
    \item \textbf{Cascaded 3-Head Classification:} Rather than performing flat classification across hundreds of combined chord names, the prediction is structured into three consecutive heads:
    \begin{enumerate}
        \item \textbf{Root Head}: Predicts the fundamental note (12 pitch classes: C, C$\sharp$, D, \ldots, B).
        \item \textbf{Quality Head}: Predicts the core triad type (major, minor, diminished, augmented, suspended).
        \item \textbf{Extension Head}: Conditioned on the predicted root and quality, predicts harmonic extensions (none, 7th, maj7, 9th, 11th, 13th).
    \end{enumerate}
\end{itemize}

Training was conducted on \textbf{Google Colab} using an NVIDIA GPU.

\subsection{End-to-End Recognition Pipeline}

The complete audio-to-chord transcription pipeline operates in five consecutive phases:

\begin{enumerate}
    \item \textbf{Audio Preprocessing:} The input audio file or streamed URL is normalized to standard mono 44.1\,kHz WAV format to ensure consistent acoustic characteristics.
    \item \textbf{Harmonic Source Separation:} Demucs isolates the harmonic accompaniment stem from the full mix, filtering out drum transients and vocal formants.
    \item \textbf{Beat Tracking and Segmentation:} madmom detects musical tempo and downbeat timestamps, segmenting the audio into beat-aligned 2-second analysis windows.
    \item \textbf{Hierarchical Chord Classification:} The MERT encoder and fine-tuned LoRA heads predict the root note, chord quality, and harmonic extension for each segment.
    \item \textbf{Music Theory Post-Processing:} Viterbi sequence smoothing removes spurious transitions, detects the song's key, and calculates Roman numeral harmonic functions and modal scale recommendations.
\end{enumerate}

\subsection{Challenges Encountered}

\begin{itemize}
    \item \textbf{Extended Chord Ambiguity:} Extended chords share most of their pitch classes with simpler triads (e.g., Cmaj9 contains all notes of Cmaj7 and Em). The team addressed this by cascading the extension prediction after root and quality classification, constraining predictions to valid chord families.
    \item \textbf{Class Imbalance in Training Data:} Common major and minor triads outnumber 9th, 11th, and 13th chords by more than a hundred-fold in standard pop music. The team resolved this by employing Focal Loss and semitone pitch-shift augmentation to enrich rare chord samples.
    \item \textbf{Multi-Instrument Polyphony:} Drums and vocals frequently mask higher piano overtones required to detect 9th and 11th chord extensions. Demucs source separation was integrated to isolate the harmonic stem prior to feature extraction.
    \item \textbf{Real-Time Inference Latency:} Live student practice requires fast feedback without noticeable lag. Model quantization and moving music theory calculations to the client browser successfully reduced turnaround time to under 100\,ms.
\end{itemize}

    \item \textbf{VN Piano Extended Chord Dataset:} First labeled benchmark for Vietnamese piano extended chords.
    \item \textbf{Client-Side Harmonic Engine:} Zero-latency browser-side Roman numeral and scale mapping.
    \item \textbf{Focal Loss + Pitch-Shift Augmentation:} Addresses class imbalance across the chord vocabulary.
\end{itemize}

\subsection*{Limitations}
\begin{itemize}
    \item \textbf{Piano-Only Scope:} Guitar and other instruments are planned as future extensions.
    \item \textbf{CPU Inference Latency:} ONNX optimization required for the 200\,ms Real-Time Practice Mode target.
    \item \textbf{Dataset Size:} Smaller than international benchmarks; extended chord accuracy may be limited.
\end{itemize}

\subsection*{Future Work}
\begin{itemize}
    \item \textbf{Multi-Instrument Extension:} Fine-tune on guitar and ukulele datasets.
    \item \textbf{Mobile Application:} Extend the workspace to a mobile app.
    \item \textbf{Sheet Music Generation:} Integrate VexFlow-based chord sheet export.
    \item \textbf{Adaptive Learning:} Spaced repetition for A/B Loop based on practice accuracy data.
\end{itemize}
